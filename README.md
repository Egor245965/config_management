# Эмулятор командной оболочки — вариант 7

Практическая работа по дисциплине «Конфигурационное управление».
Реализованы этапы 1–5: CLI, конфигурация, ZIP-VFS и команды оболочки.
Требуется Python 3.9 или новее, только стандартная библиотека.
Сборка и установка зависимостей не требуются.

## Быстрый запуск

Из корня проекта:

```text
python scripts/build_demo_vfs.py
python src/emulator.py --vfs vfs/demo.zip
```

В Windows можно использовать `run.bat --vfs vfs\demo.zip`.
BAT-файлы работают и при запуске из другого каталога.
Без `--vfs` создаётся пустая VFS с корнем `/`.

Демонстрация каждого нового этапа с правильными командами и намеренными
ошибками:

```text
scripts\test_stage4.bat
scripts\test_stage5.bat
```

На любой ОС эквивалентные команды:

```text
python scripts/build_demo_vfs.py
python src/emulator.py --vfs vfs/demo.zip --script scripts/stage4.txt
python src/emulator.py --vfs vfs/demo.zip --script scripts/stage5.txt
```

Скрипты завершаются командой `exit`. Каждая демонстрация загружает исходную
VFS заново; изменения предыдущего запуска не сохраняются.

## Этапы

| Этап | Реализация |
| --- | --- |
| 1. REPL | CLI, реальные имя пользователя и хост, кавычки, ошибки, exit |
| 2. Конфигурация | `--vfs`, `--script`, вывод параметров, стартовый скрипт |
| 3. VFS | ZIP без распаковки, Base64 в памяти, motd, ошибки загрузки |
| 4. Основные команды | Настоящие `ls`, `cd`, новые `who`, `head` |
| 5. Дополнительные команды | `mkdir`, `chmod`, изменения только в памяти |

## Настройки и стартовый скрипт

- `--vfs ПУТЬ`: физический путь к ZIP; относительный путь отсчитывается
  от рабочего каталога процесса, из которого запущен Python.
- `--script ПУТЬ`: физический путь к текстовому файлу UTF-8 с командами.
- `--help`: справка о параметрах запуска.

Параметры печатаются при старте. Из корня VFS выводится текст UTF-8 файла
`motd`, если он есть. Ошибка загрузки ZIP завершает запуск с сообщением.
Отсутствующий или нечитаемый стартовый скрипт также вызывает сообщение.

В скриптах допускаются пустые строки и комментарии `#`, в том числе после
команды. Символ `#` в кавычках является частью аргумента. Каждая команда
печатается вместе с приглашением и результатом. Ошибки команд не прерывают
остальные строки; `exit` прекращает выполнение. Скрипт и REPL используют
один сеанс, поэтому текущая папка и изменения VFS сохраняются между ними.

## Команды

| Команда | Поведение и поддерживаемые режимы |
| --- | --- |
| `ls [ПУТЬ ...]` | Сортированный список непосредственных элементов; по умолчанию текущая папка |
| `ls -a`, `ls -l`, `ls -al` | Скрытые имена и `.`/`..`; права и тип объекта; сочетание режимов |
| `cd [КАТАЛОГ]` | Смена виртуального каталога; без аргумента переход в `/` |
| `who` | Единственный сеанс эмулятора: пользователь, console, время начала, хост |
| `head ФАЙЛ ...` | Первые 10 строк текстовых файлов UTF-8 |
| `head -n N ФАЙЛ ...` | Первые N строк; N — целое неотрицательное, включая 0 |
| `mkdir КАТАЛОГ ...` | Создание каталогов с существующими родителями |
| `mkdir -p КАТАЛОГ ...` | Создание родителей; существующий каталог не считается ошибкой |
| `chmod РЕЖИМ ПУТЬ ...` | Изменение прав файлов и каталогов |
| `chmod -R РЕЖИМ ПУТЬ ...` | Изменение прав выбранного каталога и всего поддерева |
| `exit` | Завершение программы; аргументы запрещены |

Пути внутри VFS используют `/`, поддерживают абсолютную и относительную
форму, `.` и `..`. Переход выше корня остаётся в корне. Пробелы заключаются
в кавычки: `cd "My Documents"`. Пути никогда не обращаются к файлам реальной ОС.
`ls`, `head`, `mkdir` принимают `--` для окончания опций, например
`mkdir -- -directory`. У `head` параметр `-n N` указывается перед файлами.
У `chmod` опция `-R` указывается перед режимом; разрешён `--` перед режимом.

`who` моделирует сеанс этой оболочки и использует реальные имя пользователя
и имя компьютера. Перечисление остальных входов в Windows/Linux не реализовано.
`head` требует файл и не читает stdin. Команды поддерживают перечисленные
режимы, а не полный набор ключей системных UNIX-утилит.

## Права и изменения VFS

Все объекты принадлежат пользователю сеанса. Начальные права: каталоги
`755`, файлы `644`; права хостовой ОС и метаданные ZIP не используются.
Права выводятся через `ls -l`, например `drwxr-xr-x work`.

Числовые режимы `chmod`: 3 или 4 восьмеричные цифры, например `600`, `0755`.
Символьные: группы `u`, `g`, `o`, `a`, операции `+`, `-`, `=`, права `rwx`.
Поддерживаются списки через запятую: `chmod u+x,g+r,o= lines.txt`.
При отсутствии группы выбираются все группы; umask не моделируется.
Копирование прав между группами и символы `Xst` не поддерживаются.
Старшие специальные биты числового режима сохраняются и отображаются,
но механизм setuid/setgid/sticky не моделируется.

Доступ проверяется по битам владельца: чтение файла требует `r`, просмотр
каталога — `r+x`, переход и проход через каталог — `x`, создание — `w+x`
у родителя. Владелец может менять права объекта, если доступен путь к нему.
Группы и другие пользователи отдельных сеансов не имеют.

`mkdir` и `chmod` меняют только словари/множества в памяти. Исходный ZIP
не меняется; на диске не появляются виртуальные каталоги. При новом запуске
загружается исходное состояние. Команды сохранения и распаковки отсутствуют.

Пример:

```text
mkdir -p work/project/docs
chmod 700 work
ls -l /
chmod u-w work
mkdir work/denied
# Ошибка доступа ожидаема.
chmod u+w work
mkdir work/allowed
head -n 2 lines.txt
```

## Устройство программы

- `src/emulator.py`: `parse_arguments` читает настройки; `parse_command`
  разбирает кавычки и комментарии; `execute_command` передаёт команду сеансу;
  `run_startup_script` выполняет скрипт; `read_archive` строит VFS;
  `load_vfs` обрабатывает ошибки ZIP; `show_motd` выводит приветствие;
  `main` связывает запуск и `run_repl`. `get_prompt` оставлен для совместимости
  с первым этапом; рабочее приглашение формируется методом `Shell.prompt`.
- `src/shell.py`: `Shell` хранит сеанс и реализует команды;
  `options` разбирает короткие опции; `change_mode` вычисляет права через
  `parse_mode_clause` и `apply_mode_bits`. `parse_chmod_arguments` проверяет
  аргументы, а `Shell.chmod_targets` выбирает объекты для изменения прав.
- `src/virtual_fs.py`: `VirtualFS` хранит данные, разрешает пути (`resolve`),
  проверяет доступ (`require`, `require_directory`), перечисляет элементы
  (`children`), читает текст (`read_text`), создаёт папки (`mkdir`,
  `create_directory`), проверяет существование (`exists`).
  `resolve_component` обрабатывает один компонент виртуального пути.
- `tests/test_emulator.py`: проверки этапов 1–3 и совместимости.
- `tests/test_commands.py`: проверки этапов 4–5, путей, прав и неизменности ZIP.
- `scripts/build_demo_vfs.py`: генератор демонстрационной VFS; ZIP игнорируется Git.
- `scripts/stage4.txt`, `scripts/stage5.txt`: сценарии демонстрации новых этапов.
- `startup.txt`: прежний сценарий этапов 1–3, теперь выполняет реальные команды.
- `scripts/test_config.bat`, `scripts/test_script_error.bat`: проверки настроек.
- `scripts/test_vfs_*.bat`: запуск вариантов VFS предыдущего этапа.

В памяти `files` содержит Base64, `directories` — множество путей,
`modes` — числовые права. Внутренние пути не имеют начального `/`,
корень обозначен пустой строкой. `cwd` хранится отдельно в `VirtualFS`.
Загрузчик добавляет неявные родительские каталоги, включая пустые вложенные
папки, и отклоняет неоднозначные пути и конфликты файл/каталог.

## Тестирование

```text
python -m unittest discover -s tests -v
```

Или `run_tests.bat` в Windows. Тесты проверяют успешные сценарии и ошибки,
правила доступа, несколько операндов, кавычки, комментарии, EOF, сохранение
состояния сеанса и отсутствие изменений исходного архива/реальных каталогов.
Временные ZIP тестов создаются автоматически.
