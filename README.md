# Эмулятор командной оболочки — вариант 7

Практическая работа по дисциплине «Конфигурационное управление».
Реализованы этапы 1–4. Требуется Python 3.9+, только стандартная библиотека.
Сборка и установка зависимостей не требуются.

## Запуск

```text
python scripts/build_demo_vfs.py
python src/emulator.py --vfs vfs/demo.zip
```

Без `--vfs` используется пустая VFS. `--script ПУТЬ` запускает текстовый
скрипт UTF-8. Физические пути отсчитываются от рабочего каталога процесса.
В Windows доступны `run.bat --vfs vfs\demo.zip` и `scripts\test_stage4.bat`.
BAT-файлы можно запускать из любого каталога.

## Этапы 1–3

CLI использует реальные имя пользователя и хост. Парсер поддерживает
кавычки и комментарии `#`. Параметры запуска выводятся при старте.
VFS загружается из ZIP в память без распаковки; файлы хранятся в Base64.
Файл `motd` из корня выводится при запуске. Ошибки ZIP, скриптов, кавычек,
неизвестных команд и аргументов сопровождаются сообщениями.

Стартовый скрипт печатает ввод и результат, пропускает пустые строки,
продолжает работу после ошибок команд и останавливается по `exit`.
Скрипт и REPL используют один текущий виртуальный каталог.

## Этап 4: команды

- `ls [ПУТЬ ...]`: сортированный список непосредственных элементов.
- `ls -a`: скрытые имена и `.`/`..`.
- `ls -l`, `ls -al`: тип объекта и права, сочетание опций.
- `cd [КАТАЛОГ]`: смена виртуальной папки; без аргумента — корень `/`.
- `who`: сеанс эмулятора с реальным пользователем, хостом и временем начала.
- `head ФАЙЛ ...`: первые 10 строк файлов UTF-8.
- `head -n N ФАЙЛ ...`: первые N строк, включая N=0.
- `exit`: завершение без аргументов; EOF также завершает REPL.

Пути UNIX используют `/`, `.` и `..`, поддерживают абсолютную и относительную
форму. Пробелы заключаются в кавычки. Выход выше корня остаётся в корне.
`ls` и `head` поддерживают `--` для окончания опций. У `head` ключ `-n N`
указывается перед файлами. Чтение stdin не реализовано. `who` показывает
сеанс эмулятора, а не остальные входы пользователей в ОС.

Начальные права: каталоги 755, файлы 644. Владелец — пользователь сеанса.
Чтение требует r, проход по каталогам — x, просмотр каталога — r+x.
Права хостовой ОС и метаданные ZIP не используются.

## Демонстрация и тесты

```text
python scripts/build_demo_vfs.py
python src/emulator.py --vfs vfs/demo.zip --script scripts/stage4.txt
python -m unittest discover -s tests -v
```

Сценарий показывает команды, режимы и намеренные ошибки, затем выполняет
`exit`. В Windows: `scripts\test_stage4.bat` и `run_tests.bat`.

## Устройство

- `src/emulator.py`: настройки (`parse_arguments`), парсер (`parse_command`),
  выполнение (`execute_command`), скрипт (`run_startup_script`), загрузка ZIP
  (`read_archive`, `load_vfs`), приветствие (`show_motd`), `main`, `run_repl`.
  `get_prompt` сохранён для совместимости; сеанс использует `Shell.prompt`.
- `src/shell.py`: `Shell` реализует команды и сеанс; `options` разбирает ключи.
- `src/virtual_fs.py`: `VirtualFS` хранит файлы, каталоги, права и cwd;
  `resolve` разрешает пути; `exists` проверяет существование;
  `require` и `require_directory` проверяют доступ; `children` перечисляет
  содержимое; `read_text` декодирует UTF-8.
- `tests/`: тесты команд, загрузки VFS, путей, скриптов и обработки ошибок.
- `scripts/build_demo_vfs.py`: генератор игнорируемого Git файла `demo.zip`.
- `scripts/stage4.txt`: демонстрация этапа 4.
- `startup.txt`, `scripts/test_config.bat`, `scripts/test_script_error.bat`,
  `scripts/test_vfs_*.bat`: сценарии проверки этапов 1–3.

В памяти `files` содержит Base64, `directories` — множество путей,
`modes` — права; корень обозначен пустой строкой. Загрузчик создаёт
неявные родительские каталоги и отклоняет неоднозначные пути ZIP.

## Оформление репозитория

Старые ZIP этапа 3 сохранены. Методичка перечисляет архивы в Git как
нарушение оформления: перед сдачей стоит заменить старые тестовые ZIP
генератором либо согласовать их хранение с преподавателем.
Новый `demo.zip` воспроизводится из Python и игнорируется Git.
