# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

Вариант №7.

На данный момент реализованы:

- Этап 1 — REPL;
- Этап 2 — Конфигурация;
- Этап 3 — VFS.

Программа представляет собой эмулятор командной оболочки
UNIX-подобной операционной системы.

## Описание

Эмулятор работает в режиме REPL:

1. получает команду пользователя;
2. разбирает введённую строку;
3. определяет команду и её аргументы;
4. выполняет соответствующее действие;
5. выводит результат;
6. снова ожидает ввод пользователя.

Для разбора командной строки используется модуль `shlex`, благодаря чему
поддерживаются аргументы, заключённые в кавычки.

Например:

```text
cd "My Documents"
```

будет разобрано как:

```text
command = cd
args = ["My Documents"]
```

## Этап 1 — REPL

На первом этапе реализованы:

- консольный интерфейс;
- приглашение командной строки на основе данных реальной ОС;
- получение имени пользователя;
- получение имени компьютера;
- разбор команд и аргументов;
- поддержка аргументов в кавычках;
- обработка пустого ввода;
- обработка некорректных кавычек;
- обработка неизвестных команд;
- проверка количества аргументов;
- команда-заглушка `ls`;
- команда-заглушка `cd`;
- команда `exit`;
- модульные тесты.

Команды `ls` и `cd` пока являются заглушками и не выполняют реальные
операции с виртуальной файловой системой.

## Поддерживаемые команды

### `ls`

На текущем этапе команда является заглушкой.

Пример:

```text
ls
```

или:

```text
ls home documents
```

Эмулятор выводит название команды и переданные аргументы.

### `cd`

На текущем этапе команда является заглушкой.

Пример:

```text
cd home
```

Поддерживаются аргументы с пробелами:

```text
cd "My Documents"
```

Команда принимает не более одного аргумента.

При вводе:

```text
cd home documents
```

выводится:

```text
Ошибка: cd принимает не более одного аргумента
```

### `exit`

Завершает работу эмулятора.

```text
exit
```

Команда не принимает аргументы.

Например:

```text
exit hello
```

Результат:

```text
Ошибка: exit не принимает аргументы
```

После ошибки эмулятор продолжает работу.

## Обработка ошибок команд

Неизвестная команда:

```text
abracadabra
```

Результат:

```text
Ошибка: неизвестная команда 'abracadabra'
```

Неверное количество аргументов:

```text
cd home documents
```

Результат:

```text
Ошибка: cd принимает не более одного аргумента
```

Неверный вызов `exit`:

```text
exit hello
```

Результат:

```text
Ошибка: exit не принимает аргументы
```

Незакрытые кавычки:

```text
cd "My Documents
```

Результат:

```text
Ошибка: некорректные кавычки
```

После возникновения ошибки эмулятор продолжает работу.

## Приглашение командной строки

Приглашение формируется на основе данных реальной операционной системы:

```text
username@hostname:~$
```

Для получения имени пользователя используется:

```python
getpass.getuser()
```

Для получения имени компьютера:

```python
socket.gethostname()
```

## Этап 2 — Конфигурация

На втором этапе добавлена возможность настройки эмулятора с помощью
параметров командной строки.

Поддерживаются параметры:

- `--vfs` — путь к физическому расположению VFS;
- `--script` — путь к стартовому скрипту.

Пример запуска:

```text
python src\emulator.py --vfs vfs\files.zip --script startup.txt
```

При запуске выводятся заданные параметры:

```text
Параметры эмулятора:
VFS: vfs\files.zip
Стартовый скрипт: startup.txt
```

Для обработки параметров командной строки используется модуль
`argparse`.

## Стартовый скрипт

Стартовый скрипт позволяет автоматически выполнить последовательность
команд при запуске эмулятора.

Файл:

```text
startup.txt
```

поддерживает комментарии, начинающиеся с символа `#`.

Пример:

```text
# Проверка команд Этапа 1

ls
ls home documents

cd
cd home
cd "My Documents"

# Проверка ошибок

abracadabra
cd home documents
cd "Broken

# Проверка exit

exit hello
exit
```

Пустые строки и комментарии пропускаются.

При выполнении стартового скрипта на экран выводятся как сами команды,
так и результаты их выполнения.

Пример:

```text
admin@DESKTOP:~$ cd home
cd ['home']
```

Если стартовый скрипт не найден, выводится сообщение об ошибке без
аварийного завершения Python-программы.

## Скрипты проверки конфигурации

В каталоге `scripts` находятся BAT-файлы:

```text
scripts/
├── test_config.bat
└── test_script_error.bat
```

`test_config.bat` проверяет обычный запуск с параметрами конфигурации.

`test_script_error.bat` проверяет обработку отсутствующего стартового
скрипта.

## Этап 3 — VFS

На третьем этапе подключена виртуальная файловая система.

Источником VFS является ZIP-архив.

Архив не распаковывается на диск. Содержимое считывается непосредственно
из ZIP и хранится в памяти программы.

Для работы с ZIP используется стандартный модуль:

```python
zipfile
```

Содержимое файлов хранится в памяти в формате Base64.

Для этого используется модуль:

```python
base64
```

## Загрузка VFS

Для загрузки виртуальной файловой системы используется функция:

```text
load_vfs()
```

Путь передаётся через параметр `--vfs`.

Пример:

```text
python src\emulator.py --vfs vfs\nested.zip
```

После успешной загрузки выводится сообщение:

```text
VFS загружена: vfs\nested.zip
```

Функция `load_vfs()`:

- открывает ZIP-архив;
- получает список файлов и каталогов;
- определяет вложенные каталоги;
- считывает содержимое файлов;
- кодирует содержимое файлов в Base64;
- сохраняет данные в памяти;
- не распаковывает архив на диск.

## Представление VFS в памяти

После загрузки VFS хранится в виде структуры:

```text
{
    "files": {...},
    "directories": {...}
}
```

`files` содержит пути к файлам и их содержимое.

`directories` содержит каталоги виртуальной файловой системы.

Например, для структуры:

```text
home/
└── user/
    └── documents/
        └── file.txt
```

в памяти будут определены каталоги:

```text
home
home/user
home/user/documents
```

и файл:

```text
home/user/documents/file.txt
```

## Ошибки загрузки VFS

Если указанный файл не существует:

```text
Ошибка загрузки VFS: файл не найден
```

Если указанный файл существует, но не является корректным ZIP-архивом:

```text
Ошибка загрузки VFS: неверный формат ZIP
```

Для проверки неверного формата используется тестовый файл:

```text
vfs\broken.zip
```

## Файл `motd`

Если в корне виртуальной файловой системы находится файл:

```text
motd
```

его содержимое автоматически выводится после загрузки VFS.

Для этого используется функция:

```text
show_motd()
```

Например:

```text
VFS загружена: vfs\nested.zip
Добро пожаловать во вложенную VFS!
```

Файл `motd` хранится внутри ZIP-архива.

Его содержимое извлекается из памяти, декодируется из Base64 и выводится
в консоль.

Если файла `motd` нет, дополнительное сообщение не выводится.

## Варианты VFS

Для проверки работы созданы несколько ZIP-архивов.

### `minimal.zip`

Минимальная виртуальная файловая система:

```text
minimal.zip
└── motd
```

### `files.zip`

Виртуальная файловая система с несколькими файлами:

```text
files.zip
├── motd
├── readme.txt
├── notes.txt
└── data.txt
```

### `nested.zip`

Виртуальная файловая система с несколькими уровнями вложенности:

```text
nested.zip
├── motd
└── home/
    └── user/
        └── documents/
            └── file.txt
```

Эта VFS используется для проверки работы структуры с несколькими
уровнями каталогов.

## Скрипты проверки VFS

Для запуска эмулятора с различными вариантами VFS созданы:

```text
scripts/
├── test_vfs_files.bat
├── test_vfs_minimal.bat
└── test_vfs_nested.bat
```

`test_vfs_minimal.bat` запускает минимальную VFS.

`test_vfs_files.bat` запускает VFS с несколькими файлами.

`test_vfs_nested.bat` запускает вложенную VFS вместе со стартовым
скриптом.

Пример запуска:

```text
python src\emulator.py --vfs vfs\nested.zip --script startup.txt
```

При таком запуске:

1. считываются параметры командной строки;
2. загружается ZIP-VFS;
3. выводится `motd`;
4. выполняется `startup.txt`;
5. выполняются команды и проверяется обработка ошибок.

## Основные функции

### `get_prompt()`

Формирует приглашение командной строки на основе имени пользователя и
имени компьютера.

### `parse_arguments()`

Обрабатывает параметры запуска:

- `--vfs`;
- `--script`.

### `parse_command()`

Разбирает строку на команду и список аргументов.

Для разбора используется:

```python
shlex.split()
```

### `execute_command()`

Обрабатывает команды:

- `ls`;
- `cd`;
- `exit`.

Также сообщает об неизвестных командах и неправильных аргументах.

### `run_startup_script()`

Открывает стартовый скрипт и выполняет его построчно.

Поддерживает:

- пустые строки;
- комментарии;
- команды с аргументами;
- кавычки;
- обработку ошибок.

### `load_vfs()`

Загружает ZIP-архив виртуальной файловой системы.

Функция:

- работает с VFS в памяти;
- получает файлы и каталоги;
- кодирует файлы в Base64;
- обрабатывает отсутствие файла;
- обрабатывает неверный формат ZIP.

### `show_motd()`

Проверяет наличие файла `motd` в корне VFS.

Если файл существует, функция декодирует его содержимое и выводит
сообщение при запуске.

### `main()`

Главная функция программы.

Выполняет:

- обработку аргументов запуска;
- вывод параметров;
- загрузку VFS;
- вывод `motd`;
- выполнение стартового скрипта;
- запуск REPL.
